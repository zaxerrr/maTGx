# MAX2TG-Bridge

> Двусторонний мост между мессенджером **MAX** (`web.max.ru` / `api.oneme.ru`) и **Telegram** через форум-топики в супергруппе.

Каждый чат MAX становится отдельным форум-топиком в твоей супергруппе Telegram. Входящие сообщения из MAX (текст, фото, файлы, видео, голосовые, стикеры, контакты, локации, цитаты, пересланные) приходят в свой топик. Ответ написанный в этом топике уходит обратно собеседнику в MAX от твоего имени.

При создании топика автоматически постится и закрепляется карточка собеседника с именем, id и аватаром.

## Возможности

### MAX → Telegram
- Текст с сохранением форматирования (элементы MAX `STRONG`, `EMPHASIZED`, `STRIKETHROUGH`, `UNDERLINE`, `MONOSPACED`, `LINK`, цитаты → HTML Telegram)
- Фото с подписью
- Видео целиком (опкод 83, лучшее качество до 50 МБ; больше — превью-кадр)
- Документы любых типов до 50 МБ (лимит Bot API); больше — карточка с именем и размером, без скачивания
- Голосовые и аудио (когда MAX отдаёт `_type=AUDIO`; для нового `_type=UNSUPPORTED` — заглушка с длительностью)
- Стикеры
- Контакты, локации, ссылки-превью
- Ответы (reply) — нативным ответом Telegram, если исходное сообщение есть в топике; иначе цитатой
- Правки: повторно пришедшее из MAX сообщение с новым текстом правит уже отправленное в Telegram (или отвечает «✏️ Изменено»), точные дубли отбрасываются
- Сообщения одного чата доставляются строго по порядку
- Длинные тексты и подписи делятся на несколько сообщений без потери содержимого
- Уведомления о статусе подключения к MAX в General-топик (с троттлингом), отдельный алерт о протухшем токене

### Telegram → MAX
- Текст с форматированием (`STRONG`, `EMPHASIZED`, `STRIKETHROUGH`, `UNDERLINE`, `MONOSPACED`, `LINK`; цитаты уходят обычным текстом)
- Фото и статичные стикеры (photo-upload MAX, опкод 80); анимированные стикеры — превью-кадром
- Видео, GIF и видеосообщения-кружки — нативным видео MAX (опкод 82), при неудаче — файлом
- Документы, аудио (file-upload MAX, опкод 87)
- Голосовые приходят в MAX как файл `.ogg` (опкод нативной voice-загрузки пока не реверсен)
- Ответ (reply) на сообщение из MAX становится ответом в MAX
- Правка своего текстового сообщения в Telegram правит его в MAX (опкод 67)
- `/rm` ответом на своё сообщение — удалить его в MAX (опкод 66)
- Опросы, геолокация, контакты — бот честно отвечает, что это не передаётся
- Реакция 👀 на успешную доставку, текст ошибки от MAX — на провал

### Управление
- Авто-создание форум-топика на каждый новый чат MAX
- Закреплённая карточка профиля при создании топика
- Команды: `/bind`, `/add`, `/profile`, `/intro`, `/rm`, `/del`, `/help`
- Топик, удалённый вручную в Telegram, пересоздаётся автоматически при следующем сообщении
- Настройка в личке с ботом: вход в MAX по номеру+коду или токеном, выбор группы кнопками — в `.env` только `TG_BOT_TOKEN`
- Несколько аккаунтов MAX: у каждого своя группа или общая группа с подписанными темами
- Писать в MAX через мост может только владелец (первый `/start` или `TG_ALLOWED_USER_ID`)
- SOCKS5-прокси для Telegram (`TG_PROXY`)
- Карта связок переживает рестарт (`state/topics.json`, `state/messages.db` — соответствие сообщений для ответов и правок)
- Авто-переподключение к MAX и алёрт при обрыве

## Архитектура

```
  ┌────────────────┐    WebSocket    ┌──────────────────┐
  │  ws-api.       │  ◄────────────► │   max2tg (app)   │
  │  oneme.ru      │                 │  ├ MaxClient     │
  └────────────────┘                 │  ├ Resolver      │
                                     │  ├ TelegramSender│
  ┌────────────────┐    Bot API      │  └ tg_handler    │
  │ api.telegram.  │  ◄────────────► │                  │
  │ org            │                 │  state/topics.json│
  └────────────────┘                 └──────────────────┘
```

- `app/main.py` — точка входа: загружает `.env`, поднимает MaxClient (WS), Telegram Application (polling), привязывает их через TopicStore.
- `app/max_client.py` — WebSocket-клиент MAX. Опкоды auth/dispatch/send/upload, retries, reconnect.
- `app/max_listener.py` — приём сообщений из MAX, маршрутизация в Telegram-топики, авто-создание топиков, постинг карточки.
- `app/resolver.py` — кеш контактов и чатов MAX.
- `app/tg_sender.py` — отправка в Telegram, `ensure_topic` (создание форум-топиков, переименование при появлении настоящего имени).
- `app/tg_handler.py` — команды и медиа из Telegram → MAX.
- `app/topics.py` — `TopicStore`: атомарно-сохраняемая JSON-карта `max_chat_id ↔ telegram_thread_id`.

## Требования

- Python **3.12+** (для локального запуска)
- Docker + docker-compose v2 (для рекомендуемого деплоя)
- Аккаунт MAX (`web.max.ru`)
- Супергруппа Telegram с **включёнными темами** (Topics / Forum)
- Telegram-бот (через [@BotFather](https://t.me/BotFather)) — администратор супергруппы с правом «**Управление темами**»

## Установка

### 1. Бот

У [@BotFather](https://t.me/BotFather) создай бота и запиши **`TG_BOT_TOKEN`** — это единственное, что обязательно нужно в `.env`.

### 2. Запуск (Docker, рекомендованный)

```bash
git clone https://github.com/zaxerrr/maTGx.git max2tg
cd max2tg
echo "TG_BOT_TOKEN=123456:ABC..." > .env && chmod 600 .env
docker compose up -d --build
docker compose logs -f
```

### 3. Настройка в чате с ботом

1. Напиши боту в личку **`/start`** — первый написавший становится **владельцем** моста (или задай `TG_ALLOWED_USER_ID`, тогда владелец только он).
2. Бот скажет «MAX-аккаунт не подключён» и предложит:
   - **📱 По номеру телефона** (или сразу командой `/login +79991234567`) — MAX пришлёт код (SMS или в приложение MAX), пришли код боту;
   - **🔑 Прислать токен** — значение `__oneme_auth` из web.max.ru (F12 → Application → Local Storage; можно целиком JSON), затем `__oneme_device_id`.
   
   Сообщения с кодом и токеном бот сразу удаляет, токен проверяет настоящим входом в MAX.
3. Создай супергруппу, включи в ней **«Темы»**, добавь бота **администратором с правом «Управление темами»**. Бот сам заметит группу и пришлёт кнопку «Привязать» (Telegram не даёт ботам список их групп, поэтому группа появляется, когда бота в неё добавляют).
4. Готово: в General-топике появится `✅ Max: подключён`, каждый чат MAX — отдельной темой. В настройках реакций группы разреши «Все эмодзи», чтобы бот ставил 👀 на доставленные ответы.

**Несколько аккаунтов MAX:** в меню `/start` → «➕ Добавить аккаунт MAX». У каждого аккаунта своя группа; можно и одну группу на несколько аккаунтов — тогда темы подписываются именем аккаунта (`Работа · Иван`), а в `/bind`/`/add` первым аргументом указывается аккаунт. Там же — «Войти заново» (если MAX сбросил токен, бот пришлёт в личку кнопку), смена группы, удаление аккаунта.

Все настройки лежат в `state/accounts.json` (права 600 — там токены MAX), карта тем — в `state/topics.json` / `state/accounts/<id>/`. Не теряй том `./state`, иначе темы создадутся заново.

**Старый `.env` продолжает работать:** если заданы `MAX_TOKEN` + `MAX_DEVICE_ID` + `TG_CHAT_ID`, из них при старте создаётся аккаунт `main` со старыми файлами состояния; дальше им можно управлять из меню бота.

**Вход по номеру из консоли** (альтернатива диалогу):

```bash
python -m app.login --write-env .env                    # локально / systemd
docker compose run --rm max2tg python -m app.login      # в Docker: значения печатаются
```

> Токен MAX даёт полный доступ к аккаунту — не показывай никому. При входе в web.max.ru с другого устройства токен может смениться — бот пришлёт в личку «❌ авторизация не прошла» с кнопкой «Войти заново».

### 4. Локальный запуск (для разработки)

```bash
python -m venv .venv
source .venv/bin/activate   # Windows: .venv\Scripts\Activate.ps1
pip install -r requirements.txt
cp .env.example .env  # отредактировать
python -m app.main
```

### 5. systemd (Linux)

`/etc/systemd/system/max2tg.service`:
```ini
[Unit]
Description=MAX2TG-Bridge
After=network.target

[Service]
Type=simple
WorkingDirectory=/opt/max2tg
ExecStart=/opt/max2tg/.venv/bin/python -m app.main
EnvironmentFile=/opt/max2tg/.env
Restart=always
RestartSec=10

[Install]
WantedBy=multi-user.target
```

```bash
sudo systemctl daemon-reload
sudo systemctl enable --now max2tg
sudo journalctl -u max2tg -f
```

## Конфигурация `.env`

| Переменная | Обязательная | Описание |
|---|---|---|
| `TG_BOT_TOKEN` | **да** | Токен бота от @BotFather. Всё остальное настраивается в личке с ботом (`/start`) |
| `TG_ALLOWED_USER_ID` | нет | Владелец моста. Если не задан — владельцем становится первый, кто напишет боту `/start` |
| `MAX_TOKEN` + `MAX_DEVICE_ID` | нет | Старый способ: аккаунт `main` из `.env` (`__oneme_auth` / `__oneme_device_id`) |
| `TG_CHAT_ID` | нет | Группа для аккаунта `main` из `.env` |
| `MAX_CHAT_IDS` | нет | Для аккаунта `main`: обрабатывать только эти chat_id MAX (через запятую) |
| `TG_PROXY` | нет | SOCKS5-прокси для Telegram, формат `socks5://[user:pass@]host:port` |
| `MAX_PROXY` | нет | HTTP(S)-прокси для MAX (WebSocket и медиа), формат `http://[user:pass@]host:port` — например, российский выход, если MAX ограничивает IP сервера |
| `STATE_DIR` | нет | Папка состояния: `accounts.json`, темы, карта сообщений (по умолчанию `state`) |
| `REPLY_ENABLED` | нет | `false` — выключить отправку из Telegram в MAX (по умолчанию включена) |
| `DEBUG` | нет | `true` — verbose-логи + dump JSON в `debug/` (токен маскируется) |
| `SYNC_EXECUTOR` | нет | `true` — не создавать потоки (для VPS, где ОС не даёт создавать потоки). DNS тогда блокирует event loop; по умолчанию выключено |

## Команды бота

**В личке с ботом:** `/start` (меню: аккаунты, вход, группы), `/login [номер]` (вход в MAX: номер → код; `/login +79991234567` сразу запрашивает код), `/cancel` (прервать ввод).

`/login` в группе номер и код не принимает (их увидят участники) — бот удалит сообщение и даст кнопку «Войти в личке», которая сразу открывает вход.

**В группе** (только от владельца). Если в группе несколько аккаунтов MAX, в `/bind` и `/add` первым аргументом указывается аккаунт (`/bind home -123…`).

| Команда | Что делает |
|---|---|
| `/bind <chat_id или URL> [название]` | Создать топик под конкретный чат MAX. URL вида `https://web.max.ru/<chat_id>` тоже принимается. |
| `/add <https://max.ru/join/...>` | Открыть групповую/канальную ссылку MAX, создать топик и поставить карточку. |
| `/profile` | (в топике) Показать профиль собеседника MAX: имя, id, аватар. |
| `/intro` | (в топике) Перепостить и закрепить карточку профиля. |
| `/rm` | (в топике, ответом на своё сообщение) Удалить это сообщение в MAX у всех. |
| `/del` | (в топике) Удалить топик и снять связь с MAX-чатом (с подтверждением). |
| `/help` | Список всех команд. |

## Известные ограничения

1. **Голосовые TG → MAX** приходят как `.ogg` файл, а не как нативное voice-bubble: настоящий опкод MAX для voice-upload пока не реверсен (см. issue в [nsdkinx/vkmax#14](https://github.com/nsdkinx/vkmax/issues/14)).
2. **Голосовые MAX → TG** иногда приходят с `_type=UNSUPPORTED` (новый формат MAX). Опкод 84 для download — это сервис звонков, не аудио. Без рабочего download мы шлём в TG заглушку «голосовое сообщение (Xс)».
8. **Удаление в MAX** не зеркалится в Telegram — событие удаления в протоколе пока не найдено. Правки из MAX ловятся по повторной доставке сообщения с тем же id; если MAX пришлёт правку другим событием, оно будет в логе как `<<< EVENT`.
9. **Удаление в Telegram** ботам не приходит — поэтому удаление в MAX делается явно командой `/rm`.
3. **Ссылки `/u/<token>`** (user share) `/add` пока не открывает — опкод 57 ищет в chat-namespace и возвращает `not.found`. Workaround: открыть такую ссылку напрямую в MAX, авто-топик создастся при первом сообщении.
4. **Лимиты Telegram Bot API** — бот скачивает из Telegram файлы до 20 МБ (TG → MAX) и отправляет в Telegram до 50 МБ (MAX → TG). Что больше — бот сообщает об этом вместо файла.
5. **Кастомные эмодзи как реакции** — Telegram запрещает ботам ставить custom-emoji реакции, поэтому используется обычная `👀`.
6. **Phone / about** в `/profile` отсутствуют — опкод `CONTACT_GET` (32) возвращает только имя и аватар.
7. **Ротация MAX-токена** — если ты залогинишься в web.max.ru с другого устройства, токен моста может стать невалидным. Мост это замечает (ошибка авторизации или нет `AUTH_SNAPSHOT` за 30 с), присылает в General-топик «❌ Max: авторизация не прошла» и переподключается с нарастающей паузой (до 5 мин). Решение: обновить `MAX_TOKEN` в `.env` и перезапустить.

## Разработка

### Тесты

```bash
pip install pytest pytest-asyncio
pytest -q
```

Покрытие: `app/topics.py` (TopicStore), `app/config.py` (загрузка env), `app/max_listener.py` (форматирование, throttle), `app/tg_handler.py` (роутинг команд и медиа), `app/max_client.py` (опкоды, авторизация, watchdog, backoff), `app/tg_sender.py` (HTML-безопасная разбивка, пересоздание топика, ответы, правки), `app/msgmap.py`, сквозной поток MAX → TG (порядок, дубли, правки, лимиты) и TG → MAX (ответы, правки, `/rm`, медиа). 357 тестов.

## Disclaimer

1. Проект **независимый, неофициальный**, не связан с разработчиками MAX (VK Group) или Telegram (TG Messenger Inc.).
2. Использует **reverse-engineered** протокол MAX (WebSocket `ws-api.oneme.ru`). Протокол может измениться без предупреждения — мост может перестать работать.
3. Работает как **userbot** к твоему MAX-аккаунту — есть формальный риск блокировки по правилам сервиса. Используй на свой страх и риск.
4. Программа предоставляется **«как есть»**, без гарантий.
